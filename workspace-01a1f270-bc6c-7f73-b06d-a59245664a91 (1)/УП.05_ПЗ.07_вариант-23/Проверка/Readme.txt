ПРОВЕРКА СЕРВЕРА ВАРИАНТА 23 (УП.05, ПЗ.07)
=============================================

Что в папке
-----------
check-server.ps1   — проверка всех 5 сценариев в PowerShell (зелёный/красный результат)
check-server.bat   — то же самое через настоящий curl.exe, для cmd
data\ok.json        — тело запроса «правильные данные»      (тема + оценка 5)
data\empty.json     — тело запроса «пустые данные»          (пустые поля)
data\bad-score.json — дополнительно: оценка 9, вне 1–5

Как запускать
-------------
1) В ПЕРВОМ окне PowerShell — поднять сервер:
       cd УП.05_ПЗ.07_вариант-23
       node server.js
   (окно не закрывать, сервер должен работать)

2) Во ВТОРОМ окне PowerShell — запустить проверку:
       cd УП.05_ПЗ.07_вариант-23\Проверка
       powershell -ExecutionPolicy Bypass -File .\check-server.ps1

   Проверка эмуляции (порт 3624, реальный сервер при этом можно остановить):
       node ..\mock-server.js
       powershell -ExecutionPolicy Bypass -File .\check-server.ps1 -base http://localhost:3624

   Вариант через cmd:
       check-server.bat

Ожидаемый результат
-------------------
 [ OK ] 1. Главная страница       -> код 200
 [ OK ] 2. Правильные данные      -> код 200
 [ OK ] 3. Пустые данные          -> код 400
 [ OK ] 4. Неверный адрес         -> код 404
 [ OK ] 5. Неверный метод         -> код 405
 [ OK ] 6. Оценка вне 1-5 (доп.)  -> код 400

Почему ваши команды не сработали (и как правильно)
--------------------------------------------------
1. В PowerShell слово curl — это НЕ curl, а псевдоним (alias) для Invoke-WebRequest.
   Он не понимает ключи -i -X -H -d, поэтому PowerShell начинал спрашивать «Uri:».
   Решения:
       - писать curl.exe ...            (настоящий curl есть в Windows 10/11)
       - или использовать Get-WebRequest/Invoke-RestMethod (см. ниже)

2. Перенос строки в PowerShell — обратный апостроф ` в конце строки, а НЕ обратный слеш \.
   В cmd перенос — ^. Проще писать команду в одну строку.

3. Кавычки: в PowerShell внешние кавычки одинарные, JSON — в них как есть:
       curl.exe -X POST http://localhost:3623/%D0%BE%D0%BF%D1%80%D0%BE%D1%81 `
         -H "Content-Type: application/json" `
         --data-binary '@data\ok.json'

4. Кириллица в адресе и в теле.
   - Адрес лучше писать в процентном виде: /опрос = /%D0%BE%D0%BF%D1%80%D0%BE%D1%81
   - Тело в PowerShell 5.1 по умолчанию уходит не в UTF-8, и сервер отвечает 400
     «Заполните все поля» даже на правильные данные. Поэтому надёжнее отправлять
     файл: --data-binary @data\ok.json  (скрипт .ps1 так и делает — читает байты UTF-8).

Проверка одной командой (PowerShell, без file — по-правильному)
---------------------------------------------------------------
   Invoke-RestMethod -Uri http://localhost:3623/
   Invoke-RestMethod -Uri 'http://localhost:3623/%D0%BE%D0%BF%D1%80%D0%BE%D1%81' `
       -Method Post -ContentType 'application/json; charset=utf-8' `
       -Body ([System.Text.Encoding]::UTF8.GetBytes('{"тема":"Удобство расписания","оценка":5}'))

Проверка в браузере
-------------------
   http://localhost:3623/  — должна открыться страница «Сервер работает»

Коды ответов сервера (эталон для отчёта)
-----------------------------------------
   GET  /                    200  <h1>Сервер работает</h1>
   POST /опрос  правильный   200  {"status":"ok", ... }
   POST /опрос  пустые поля  400  {"error":"Заполните все поля", ...}
   GET  /неверный-адрес      404  {"error":"Не найдено"}
   GET  /опрос               405  {"error":"Метод не разрешён","allowed":"POST"}
   POST /опрос  формой       415  {"error":"Неподдерживаемый тип содержимого", ...}
